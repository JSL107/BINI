# 게임 아트 직군 확장 + 직군 태그 분리 — 설계 문서

- **작성일**: 2026-09-15
- **상태**: 설계 승인됨 (구현 대기)
- **기준**: 게임 원화 · 캐릭터 원화

## 1. 개요

현재 게임잡 스크래퍼는 원화 직군(`condition[duty]=5`) 하나만 수집한다. 이 문서는 수집
범위를 아트 4개 직군으로 넓히면서, 늘어난 공고가 원화 목록을 덮지 않도록 **직군을 태그로
분리**하는 설계를 정한다. 아울러 지금 목록에 섞여 있는 채용 대상 밖 공고(학원 강사·웹툰·
비아트 직군)를 수집 단계에서 걷어낸다.

핵심은 두 축을 나누는 것이다.

| 축 | 하는 일 | 대상 |
|---|---|---|
| **축 A — 제외** | 채용 대상 자체가 아닌 공고를 버린다 | 학원 강사, 웹툰·출판, 프로그래머·기획·시나리오, 아이콘·잡화 디자인 |
| **축 B — 태그** | 버리지 않고 직군만 표시한다 | 원화, 모델링, 애니메이션, 이펙트 |

3D 모델러는 원화가 아니지만 게임 아트다. 버리는 대신 `모델링` 태그를 붙여 원화 탭과
섞이지 않게 한다.

## 2. 배경 — 실측 근거

2026-09-15 기준으로 게임잡과 사람인을 직접 호출해 측정했다.

### 2.1 현재 수집 목록(duty=5)의 구성 — 3페이지 120건

| 분류 | 건수 | 비율 | 처리 |
|---|---:|---:|---|
| 캐릭터 원화 | 28 | 23% | 유지 |
| 배경·컨셉 원화 | 24 | 20% | 유지 |
| 원화·2D 아트(일반) | 31 | 25% | 유지 |
| 원화 아닌 직군(UI·기획·프로그래머·아이콘) | 13 | 11% | **축 A 제외** |
| 교육·학원 강사 | 5 | 4% | **축 A 제외** |
| 웹툰·출판 | 1 | 1% | **축 A 제외** |
| 판정 불가(아트PM·아트디렉터·애니메이터·전 부문 모집) | 18 | 15% | 축 B 태그 |

기준 밖이 약 15%다. 대표 사례:

```
[SBS아카데미게임학원] 평일 게임원화 강사 모집
[전국/온라인] 아트트리아카데미 웹툰/일러스트/게임원화 강사 모집
[청월당(로켓AI)] 웹툰 작가 채용
[컴투스] 카툰 렌더링&그래픽스 프로그래머 (3년 이상)
[NC][Blade&Soul] 게임 내 아이템, 아이콘 디자이너 모집
```

### 2.2 직군 코드별 수확량

게임잡은 `condition[duty]`에 21개 직군을 두고 있다. 아트 계열 4개만 대상으로 한다.

| duty | 직군 | 1페이지 |
|---:|---|---:|
| 5 | 원화 | 40 |
| 6 | 모델링 | 40 |
| 7 | 애니메이션 | 40 |
| 8 | 이펙트·FX | 40 |

UI(4)·영상제작(11)·플랫폼 디자인(13)·BX(14)는 이번 범위에서 제외한다. 기획·개발·사운드
계열도 제외한다.

### 2.3 직군 필터만으로는 새는 공고가 있다

게시자가 직군을 여러 개 달 수 있어, 원화 공고가 duty=5 밖에만 있는 경우가 나온다.

```
[넥슨코리아] 빈딕투스 디파잉 페이트 배경 컨셉 아티스트 (아르바이트)
  → duty=7(애니메이션)에만 등록됨. duty=5에는 없음
```

duty 6·7·8을 함께 수집하면 이런 누수가 자연히 회수된다. 이것이 범위를 넓히는 두 번째 이유다.

### 2.4 사람인은 키워드 검색을 유지한다

직무 카테고리(`cat_kewd`)로 바꾸는 방안을 검토했으나 실측 결과 **키워드 검색이 더 정확**했다.

| 방식 | 건수 | 기준 부합 |
|---|---:|---:|
| 카테고리 1562(원화) | 41 | 51% |
| 키워드 `게임 원화` | 29 | **72%** |

카테고리가 부정확한 이유는 둘이다. 게시자가 카테고리를 중복 선택할 수 있어 "부문별 통합
채용" 공고가 모든 칸에 들어가고, 사람인의 "원화"는 게임 한정이 아니라 애니메이션 원화
(동화·채색)와 패션 소재 디자이너까지 포함한다.

```
카테고리에만 있고 키워드에 없는 공고 (대부분 기준 밖)
  (주)스튜디오미르        2D 애니메이션 원화가 채용      ← 애니메이션 업계
  (주)더그림엔터테인먼트   웹툰 원화·IP 아트워크          ← 웹툰
  (주)비케이브            가방·액세서리 디자이너         ← 패션
```

다만 카테고리만 잡아낸 진짜 게임사 공고도 있었다(`[(주)코그] 2D캐릭터`). 제목에 "게임"도
"원화"도 없어 키워드가 놓친 경우로, 카테고리 전환이 아니라 **질의 추가**로 대응한다.

## 3. 확정된 결정

| # | 결정 |
|---|---|
| 1 | 축 A 제외 필터를 수집 단계에 도입한다 |
| 2 | 사람인·잡코리아는 키워드 검색을 유지하고 질의를 늘린다 (카테고리 전환 안 함) |
| 3 | 원화 공고를 캐릭터 / 배경·컨셉으로 나눠 태그를 붙인다 |

| 5 | 애니메이터는 축 A(제외)가 아니라 축 B(태그)로 처리한다 |

## 4. 설계

### 4.1 수집 범위 확장

`GamejobScraperService.fetchJobList(page)`가 지금은 `condition[duty]=5` 한 번만 호출한다.
직군 배열을 돌며 호출하고 결과를 합친다.

```
ART_DUTIES = [
  { code: '5', family: '원화' },
  { code: '6', family: '모델링' },
  { code: '7', family: '애니메이션' },
  { code: '8', family: '이펙트' },
]
```

같은 공고가 여러 직군에 등록되어 있으면 `GI_No`가 같다. **합치는 시점에 `GI_No`로 묶고
직군은 배열로 누적**한다. 넥슨 사례처럼 한 공고가 원화와 애니메이션 양쪽에 달린 경우
`['원화', '애니메이션']`이 된다.

HTTP 호출은 페이지당 4회로 늘어난다. 직군 간에는 순차가 아니라 병렬(`Promise.allSettled`)로
보내고, 한 직군이 실패해도 나머지는 진행한다. 기존 소스 실패 정책과 같다.

### 4.2 직군 태그는 어디서 오는가

현재 파서가 채우는 `RawJob.tags`에는 **직군이 들어 있지 않다.** 실제 담기는 값은 이렇다.

```
tags: [경력2년↑ | 학력무관 | 경기 > 성남시 | 모바일게임 | 정규직]
```

직군은 목록 HTML의 `onclick` 속성 안에만 있다.

```html
<a href="/Recruit/GI_Read/View?GI_No=284897"
   onclick="GA_Application_Prdt('02_공고클릭', 'N', '<제목>', '284897', '<회사>', '없음',
            IsNullOrWhiteSpace('원화, 애니메이션, 이펙트·FX'),
            IsNullOrWhiteSpace('RPG'), '없음',
            IsNullOrWhiteSpace('서울 > 마포구'));">
```

`IsNullOrWhiteSpace(...)` 인자가 순서대로 **직군 · 장르 · 지역**이다. 첫 번째를 쉼표로
쪼개면 게시자가 직접 단 직군 목록이 그대로 나온다. 제목에서 추측하는 것보다 정확하므로
이 값을 직군 태그의 출처로 삼는다.

파서는 이미 `onclick`을 읽고 있다(`extractOnclickTitle`). 같은 문자열에서 직군을 추가로
뽑으면 되고, 새 HTTP 요청은 필요 없다.

요청한 duty 코드가 아니라 **공고가 실제로 달고 있는 직군 목록**을 저장한다. duty=6으로
받아온 공고가 직군에 `원화`도 달고 있으면 그 사실이 보존되어야 한다.

### 4.3 원화 하위 구분(캐릭터 / 배경·컨셉)

게임잡의 직군 라벨에는 `원화` 하나뿐이고 캐릭터와 배경을 나눠주지 않는다. 제목에서 뽑는
수밖에 없다. 실측상 duty=5 120건 중 43%가 제목만으로 갈렸다(캐릭터 28 · 배경·컨셉 24).

| 하위 구분 | 제목 단서 |
|---|---|
| `캐릭터` | 캐릭터, character |
| `배경·컨셉` | 배경, 컨셉, 콘셉, concept, environment |
| (없음) | 위 어느 쪽도 아니면 하위 구분 없이 `원화`로만 둔다 |

둘 다 걸리는 제목(`유니티 3D 캐릭터 / 배경 / 애니메이터`)은 둘 다 붙인다. 배열이므로
배타 선택을 강제하지 않는다.

**직군이 `원화`인 공고에만 적용한다.** 모델링 직군의 "3D 캐릭터 모델러"에 `캐릭터` 하위
구분이 붙으면 원화 탭에 3D 모델러가 올라온다. 실측에서 duty=6의 캐릭터 포함 공고 15건이
대부분 3D 모델러였다.

### 4.4 축 A — 제외 필터

제목을 기준으로 판정하고, 걸리면 수집 단계에서 버린다. 직군 라벨이 아트 계열이어도 면제하지
않는다. 실측에서 웹툰 작가 공고가 `원화` 직군을 달고 있었다.

단서는 실제로 관측한 것과 같은 계열이라 넣은 것을 구분해 둔다. 관측되지 않은 단서는
정탐을 죽일 위험이 있으므로 아래 계수 로그로 감시한다.

같은 계열이라는 이유로 추론해 넣었던 단서(튜터, 멘토, 출판, 표지, QA, 배너, 쇼핑몰, 패키지,
만화, 마케팅)는 병합 전 리뷰에서 실제 게임 아트 공고를 오탐으로 제외하는 것이 재현돼
전부 제거했다 — 예: "인게임 이벤트 배너 일러스트레이터", "웹툰풍 게임 원화가", "사수
멘토링 프로그램 운영". 지금 코드에 남은 단서는 전부 실측에서 관측한 것이다.

| 규칙군 | 관측된 단서 | 같은 계열로 추가한 단서 (미관측) |
|---|---|---|
| 교육·강사 | 강사, 아카데미, 학원, 교육생, 양성과정, 국비 | (없음) |
| 웹툰·출판 | 웹툰, 인스타툰 | (없음) |
| 비아트 직군 | 프로그래머, 기획자, 시나리오, 사업PM, GM(게임운영) | (없음) |
| 아트 밖 디자인 | 아이콘, 가방, 액세서리, 상세페이지 | (없음) |

**과잉 제거를 감시한다.** 각 규칙이 몇 건을 걸렀는지 규칙 단위로 세어 cron 로그에 남긴다.
어느 규칙이 갑자기 많이 거르기 시작하면 정탐을 죽이고 있다는 신호다. 이 저장소가 겪어 온
"조용히 0건"류 사고를 막는 장치다.

애매한 제목(`아트 PM`, `아트 디렉터`, `전 부문 모집`)은 **버리지 않는다.** 원화 채용을 겸하는
경우가 있어 제외 비용이 유입 비용보다 크다.

### 4.5 키워드 질의 확장

사람인·잡코리아의 `QUERY` 상수를 배열로 바꾸고 결과를 합친다. 사이트별 공고 ID로 중복을
제거한 뒤 축 A 필터를 적용한다.

| 질의 | 사람인 1페이지 | 앞 질의까지의 누적 고유 |
|---|---:|---:|
| `게임 원화` (현행) | 29 | 29 |
| `캐릭터 원화` | 40 | 50 |
| `컨셉 아티스트` | 40 | 86 |
| `게임 일러스트` | 40 | 121 |
| `원화가` | 40 | 131 |

누적값은 위 순서대로 다섯 질의를 모두 넣었을 때의 값이다. 일부만 고르면 누적은 달라지며,
그 조합은 측정하지 않았다.

우선 `게임 원화`·`캐릭터 원화`·`원화가` 세 개로 시작한다. `컨셉 아티스트`·`게임 일러스트`는
증분이 크지만(각 35건 이상) 마케팅·3D 모델러·편집 디자이너가 섞여 나왔고 개별 정확도를 재지
않았다. 축 A 필터를 한 회차 돌려 실제 정화율을 본 뒤 추가를 판단한다.

## 5. 데이터 모델

`Job.tags`는 사이트 원문 문자열을 그대로 담아 카드에 칩으로 렌더링하는 컬럼이다
(`JobCard.tsx`). 여기에 직군을 섞으면 칩 목록이 오염되고, 탭 분리를 위한 질의도 배열
부분일치에 의존하게 된다.

이 저장소는 이미 **파생 속성을 별도 컬럼에 저장하고 UI 필터가 그 컬럼을 보는** 방식을 쓰고
있다(`job-attributes.ts` → `experienceLevel` · `employmentType` · `locations` · `isRemote`).
같은 관례를 따른다.

```prisma
model Job {
  // ...
  // 게시자가 단 직군 라벨. 예: ["원화"], ["원화","애니메이션"], ["모델링"]
  jobFamilies  String[] @default([])
  // 원화 하위 구분. 예: ["캐릭터"], ["배경·컨셉"], []
  artSubtypes  String[] @default([])

  @@index([jobFamilies])
}
```

기존 공고는 `jobFamilies`가 빈 배열로 남는다. 다음 cron 회차에 같은 공고가 다시 수집되면
채워지므로 별도 백필은 두지 않는다. 다만 **빈 배열을 "직군 없음"으로 읽어 원화 탭에서
빼면 기존 공고가 통째로 사라진다.** 조회 계층은 빈 배열을 제외 조건으로 쓰지 않는다.

| `apps/web/src/components/JobCard.tsx` | 직군 배지 표시 |

`fetchJobList`는 결과가 0건이면 "구조 변경 의심"으로 예외를 던진다. 직군별로 호출이
쪼개지므로 **직군 하나가 0건인 것과 전 직군이 0건인 것을 구분**해야 한다. 전자는 정상일 수
있고(사운드처럼 공고가 적은 직군), 후자만 구조 변경 신호다.

## 7. 검증

- **파서 단위 테스트** — `onclick` 직군 추출과 하위 구분을 실제 HTML 픽스처로 단언한다.
  직군이 여러 개인 공고, 직군이 비어 있는 공고를 각각 포함한다.
- **제외 필터 테스트** — §2.1에서 실제로 관측한 제외 대상 제목을 그대로 픽스처로 쓴다.
  동시에 **제외되면 안 되는 제목**(`아트 디렉터`, `전 부문 모집`, `배경 컨셉 아티스트`)도
  넣어 과잉 제거를 잡는다.
- **수집 1회 실행** — 직군별 수신 건수, 규칙별 제외 건수, 직군 태그 분포를 로그로 확인한다.
- **표본 육안 검증** — 수집 결과 20건을 눈으로 확인해 직군 태그와 하위 구분이 맞는지 본다.
  §2.1의 분류 비율은 제목 규칙으로 센 값이라 사람 확인이 한 번 필요하다.

## 8. 범위 밖

- **UI·영상·BX 등 나머지 아트 직군** — duty 4·11·13·14. 이번엔 넣지 않는다.
- **기획·개발·사운드 계열** — duty 1·2·3·9·10·12·16~20.
- **자체 채용 페이지(그리팅 ATS 등)** — 국내 게임사 43곳이 43개 도메인을 쓴다. 회사별 파서가
  필요해 비용 대비 효율이 낮다. 위 작업을 돌려보고 부족하면 그때 판단한다.
- **해외 잡보드(ArtStation Jobs·Hitmarker)** — 원격 가능 공고 한정이라 별도 판단이 필요하다.
- **캐릭터/배경 탭 UI** — 컬럼이 생긴 뒤 별도로 설계한다. 이 문서는 데이터까지만 정한다.

## 9. 미확인 사항

- **§2.1 분류 비율은 제목 규칙으로 센 값이다.** 게임잡이 캐릭터/배경을 구분해 주지 않아
  제목으로 추정했고, "판정 불가 15%"는 공고 본문을 봐야 갈린다. §7의 표본 육안 검증으로
  규칙 정확도를 한 번 확인해야 한다.
- **duty 6·7·8의 축 A 제외율을 측정하지 않았다.** duty=5만 3페이지 분류했다. 모델링·
  애니메이션 직군에 학원 강사가 더 많을 수 있다.
- **사람인 추가 질의(`컨셉 아티스트`·`게임 일러스트`)의 개별 정확도를 재지 않았다.**
  합집합 증가분만 셌다.
- **잡코리아에 원화 직무 카테고리가 있는지 확인하지 않았다.** 키워드 유지 결정에는 영향이
  없다.
- **소스 간 중복 증가량을 측정하지 못했다.** 서버가 내려가 있어 파이프라인 실측이 불가능했다.
- **신규 질의를 붙일 사이트의 이용약관·robots.txt를 확인하지 않았다.** 게임잡·사람인·
  잡코리아는 현재도 수집 중이라 현상 유지다.
